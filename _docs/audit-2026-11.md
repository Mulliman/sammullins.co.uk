  - `/`, `/cv/`, `/xstatic14/`
  - `/articles/` + 9 articles (two of them are near-duplicates: `xstatic-adds-git-and-ftp-support` and `xstatic-introduces-git-and-ftp-support`)
  - `/software/` + 8 products, xStatic docs (8 pages + 8 "extending v2" subpages), XPEDITE docs (2)
  - `/photography/`, `/photography/photoshare21/` + 8 albums (lightbox galleries)
- **Media:** 1,020 files / 368 MB in `/media/{umbraco-id}/`. Only **306 are referenced** (~132 MB). The rest are unused pre-generated crops (`--300x0`, `--600x0`, …). There are 208 originals (~142 MB).
- **Third parties loaded on every page:** Google Fonts (CSS + font files), Google Analytics **UA-38853753-1**. Universal Analytics shut down in 2023, so this tag sends data nowhere and should go.
- **JS:** UIkit + uikit-icons (vendored, from 2021). The only real interactivity is the parallax hero, the mobile nav and the lightbox.
- **Security headers:** only HSTS. No CSP, no `X-Content-Type-Options`, no `Referrer-Policy`, no `Permissions-Policy`, no frame protection.
- **Content positioning:** "Certified Umbraco and Sitecore web developer… 10 years ASP.Net". There are no mentions of AI/Claude. Contact links are Twitter and a gmail address.
- `21-02-2026/` is a byte-identical copy of the xStatic output. It's a backup and can be archived.

## 2. SamMullins2026 (Astro 6 + React): state

| Area | Finding |
|---|---|
| Build | `astro build` succeeds but produces **5 pages**. Every collection logs *"does not exist or is empty"*. |
| Root cause | `.mdx` content but **`@astrojs/mdx` is not installed**, plus a stale legacy `src/content/config.ts` sitting beside `src/content.config.ts`. |
| Content | ~22 of 50 pages migrated, all short (329 lines total). Missing: 7 articles, all 8 photo albums, sage-of-empires, umbracofolio, 6 xStatic v2 subpages, xstatic14. |
| Components | 23 `UF*` components, a 1:1 port of the Umbraco partials. `set:html` raw-HTML injection is used in 12 places. Pages are hand-coded `.astro` files with inline data arrays, **not** content-driven block lists. |
| Dependencies | React + react-dom are installed but unused (no islands). UIkit 2021 JS is vendored. |
| Repo hygiene | Uncommitted changes, test files in `public/assets/test/`, all 368 MB of media copied into `public/`. |
| Spec | It explicitly says "preserve the exact UIkit classes". That locks in the 2021 design and its accessibility debt. |

**Verdict: keep the *decision* (Astro), don't continue the *code*.** The project is a faithful port of the old architecture: hand-built pages, UIkit, raw HTML strings. That's the opposite of "AI composes pages from components in any order". About 10% of the content is done, the build is broken, and the most valuable part (the URL inventory and component list) is cheap to redo. Start a clean repo and treat SamMullins2026 as reference.

## 3. Has anything better appeared in the last year?

| Option | For | Against | Verdict |
|---|---|---|---|
| **Astro 6 (fresh)** | Content Layer + Zod gives typed, validated block lists, so a bad AI edit fails the build instead of shipping. Zero JS by default. `astro:assets` makes responsive images at build time (removes the 714 junk crops). Built-in CSP support with hashes for scripts/styles. Now backed by Cloudflare (Jan 2026) and still MIT. | npm dependency tree (~300 packages), which is a supply-chain surface at **build time only** | **Recommended** |
| Hugo | Single Go binary, no node_modules, so the smallest supply-chain surface of any option | Go templates are clunky for typed components and there's no schema validation of front matter. AI writes it fine, but nothing catches errors. | Strong runner-up if you weigh security above everything |
| Eleventy v3 | Lighter than Astro, very flexible | No typed content schemas, weaker component model | No advantage here |
| Git-backed CMS UI (Keystatic, TinaCMS, Decap, Pages CMS) | Nice editing UI on top of the files | Adds an admin route, OAuth and a third-party service: **new attack vectors**. You'll be editing through Claude Code anyway. | Skip. The schema *is* the CMS. Add Keystatic later in local-only mode if you ever want a GUI. |

### Recommended shape

```
src/content/pages/**/*.md      ← every page = frontmatter `blocks:` array + optional markdown body
src/content.config.ts          ← Zod discriminatedUnion of block types (hero, richText, cardGrid, gallery, quote, code, cta, timeline…)
src/blocks/*.astro             ← one component per block type; <Blocks> renders them in order
redirects.ts                   ← old→new map, generated into Netlify _redirects
tests/legacy-urls.txt          ← all 50 old URLs + referenced media; CI fails if any 404s
```

That is the Umbraco Block List model, but in YAML. Claude can write a page by emitting a `blocks:` list, the schema rejects anything malformed, and `.claude/skills/new-page` can document the block catalogue for AI use. Plain Markdown/YAML rather than MDX means content can't execute code.

### Attack-surface reduction
- **Fully static output.** No Netlify Functions, Forms or Identity, and no admin UI. The served surface becomes plain files plus headers.
- **Strict `_headers`:** CSP `default-src 'self'` with hashed inline scripts, `frame-ancestors 'none'`, nosniff, a strict referrer policy, a locked-down Permissions-Policy.
- **No third-party requests:** self-host fonts, drop dead GA (or use Netlify's server-side analytics, which runs no JS), drop UIkit and React. Write the small amount of delight in vanilla JS/CSS.
- **Supply chain:** pnpm with `minimumReleaseAge` (wait N days before using new versions), postinstall scripts blocked by default, an exact lockfile, a minimal dependency list (astro, sharp, sitemap), and Dependabot/Renovate with a cooldown.
- **Build on Netlify from a private or public GitHub repo** with deploy previews limited to your own branches.

## 4. Links and redirects
- Keep `trailingSlash: 'always'` + `build.format: 'directory'` so every surviving URL is byte-for-byte the same.
- Retired pages get 301s to the closest new page (e.g. old Umbraco articles go to a `/archive/` or the relevant software page), never a 404.
- Keep the 306 referenced `/media/...` paths reachable, because GitHub READMEs, our.umbraco.com and the npm/NuGet listings hotlink them. Either keep the files at the same paths or 301 them to optimised versions.
- Add a CI check that requests every legacy URL against the built `dist/` plus `_redirects`.
